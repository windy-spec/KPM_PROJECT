BRD - Bảng Báo giá & Chi tiết Báo giá (UI + Giải thích mã)

- Màn hình 2 (Danh sách Báo giá): cho phép Admin/Sales theo dõi trạng thái các báo giá, mở chi tiết hoặc mở nhanh bằng double‑click.
- Màn hình 3 (Chi tiết Báo giá): hiển thị chi tiết bảng bóc tách (cost breakdown), upload bản vẽ lên cloud và lưu attachment, đồng thời cung cấp thao tác chốt/hủy báo giá.

- Các file đã thêm
- `frontend/src/pages/quotations/QuotationList.jsx` — component danh sách (Data-Grid) lấy dữ liệu từ `GET /api/quotations`.
- `frontend/src/pages/quotations/QuotationDetail.jsx` — component chi tiết báo giá, quản lý upload file và action panel, sử dụng `GET /api/quotations/:id`.
- `frontend/src/services/admin.service.js` — bổ sung các method: `getQuotations`, `getQuotation`, `updateQuotationStatus`, `createQuotationAttachment`.
- `frontend/src/pages/admin/Dashboard.jsx` — đã đăng ký hai panel mới: `quotations` và `quotation_detail`.
- `frontend/src/components/admin/AdminSidebar.jsx` — đã thêm mục sidebar `Danh sách Báo giá` (panel: `quotations`).

- 1) Bảng Báo giá (QuotationList.jsx)
- `load()` gọi `adminService.getQuotations({ page: 1, limit: 200 })` và lưu kết quả vào biến state `rows`.
- Các cột hiển thị: `Mã Báo Giá` (id rút gọn), `Ngày tạo`, `Tổng tiền` (định dạng VNĐ), `Trạng thái` (badge màu), `Hành động`.
- Badge trạng thái dùng màu để phân biệt: `draft` → vàng/amber, `approved` → xanh lá (teal), `cancelled` → đỏ (rose).
- Hành động: nút `Xem` gọi callback `onOpen(id)` (Dashboard truyền vào). Dashboard sẽ lưu `id` vào `localStorage` và chuyển `activePanel` sang `quotation_detail` để mở chi tiết.
- Ngoài ra, người dùng có thể double‑click một dòng để mở chi tiết nhanh.

- 2) Chi tiết Báo giá (QuotationDetail.jsx)
- Lấy `id` từ `quotationIdProp` (nếu được truyền) hoặc từ `localStorage.activeQuotationId`.
- `load()` gọi `adminService.getQuotation(id)` và lưu đáp án vào `data`.
- Phần "Hóa đơn chi tiết" sẽ render `data.dimensions.breakdown_costs` hoặc `data.breakdown_costs` (tùy backend trả trường nào):
  - Mỗi mục hiển thị `name` và `amount` (định dạng VNĐ).
  - Tổng tiền hiển thị từ `data.total_amount` hoặc `data.total`.

- 3) Upload bản vẽ (Attachments)
- FE dùng hàm `uploadToCloud(file)` để upload trực tiếp file lên dịch vụ Cloud (ví dụ Cloudinary). Sau khi upload thành công FE nhận về `fileUrl` (ví dụ `secure_url`).
- Implementation hiện tại mong đợi biến client `window.CLOUDINARY_UPLOAD_URL` (endpoint upload unsigned) và tùy chọn `window.CLOUDINARY_UPLOAD_PRESET` nếu cần preset unsigned.
- Sau khi có `fileUrl`, FE gọi `adminService.createQuotationAttachment(id, { name: file.name, file_url: fileUrl })` để BE lưu metadata (tên và URL) vào database.
- Ghi chú: FE **không** gửi trực tiếp file nặng lên BE — BE chỉ nhận metadata (tên + URL).

- 4) Action Panel (Chốt/Hủy báo giá)
- Nếu `data.status === 'draft'` thì hiển thị hai nút: `CHỐT ĐƠN` (gọi `updateQuotationStatus(id, { status: 'approved' })`) và `HỦY BÁO GIÁ` (gọi `updateQuotationStatus(id, { status: 'cancelled' })`).
- Sau khi thay đổi trạng thái, FE gọi lại `load()` để refresh dữ liệu và UI.
- Nếu trạng thái đã là `approved` hoặc `cancelled` thì hai nút trên sẽ không hiển thị (không cho phép lùi trạng thái).

- 5) Tích hợp với Admin Dashboard
- Dashboard hiện render `QuotationList` khi `activePanel === 'quotations'` và render `QuotationDetail` khi `activePanel === 'quotation_detail'`.
- Luồng điều hướng: QuotationList → gọi `onOpen(id)` → Dashboard set `activePanel='quotation_detail'` và lưu `id` vào `localStorage` → QuotationDetail đọc `id` từ `localStorage`.
- Ghi chú: đây là cơ chế đơn giản để truyền id giữa các panel mà không cần store toàn cục. Nếu bạn muốn, có thể refactor dùng `React Context` hoặc store chung để xử lý tốt hơn.

- 6) Giả định về API
- `GET /api/quotations` trả về `{ data: [ { id, created_at, total_amount, status, ... } ] }`
- `GET /api/quotations/:id` trả về `{ data: { id, created_at, total_amount, status, dimensions: { breakdown_costs: [...] }, attachments: [...] } }`
- `PUT /api/quotations/:id` chấp nhận cập nhật một phần, ví dụ `{ status: 'approved' }`.
- `POST /api/quotations/:id/attachments` chấp nhận payload `{ name, file_url }` để lưu attachment.

- 7) Xử lý lỗi & trải nghiệm người dùng
- Tất cả các cuộc gọi mạng đều được bọc trong `try/catch` và hiển thị lỗi bằng `showError(...)` nếu backend trả message lỗi.
- Các nút bị vô hiệu hóa trong khi đang tải hoặc đang upload để tránh gửi nhiều request trùng lặp.

- 8) Cấu hình Cloudinary (ví dụ)
- Đặt trong console trình duyệt hoặc lúc khởi tạo app (bootstrap):
-  - `window.CLOUDINARY_UPLOAD_URL = 'https://api.cloudinary.com/v1_1/<cloud_name>/auto/upload'`
-  - `window.CLOUDINARY_UPLOAD_PRESET = '<your_unsigned_preset>'` (nếu cần)
- Hoặc thay `uploadToCloud` bằng SDK khác (Firebase, AWS S3 presigned URL, v.v.) tuỳ hạ tầng của bạn.

- 9) Bước tiếp theo / cải tiến đề xuất
- Thay cơ chế truyền `id` qua `localStorage` bằng `React Context` hoặc route `/admin/quotations/:id` để hỗ trợ deep-linking và UX tốt hơn.
- Thêm progress bar cho upload và hỗ trợ upload nhiều file cùng lúc.
- Thêm phân trang/lọc/sắp xếp cho Quotation Grid.
- Thêm tìm kiếm server-side theo khách hàng, trạng thái, khoảng ngày.
