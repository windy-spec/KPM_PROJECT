ADMIN PART 1

Mục tiêu của phần này
- Biến khu admin thành một dashboard đúng nghĩa: admin vào là thấy trang chủ quản trị.
- Cho sidebar điều khiển panel bên trong cùng một trang, thay vì nhảy sang nhiều route rời.
- Đồng bộ modal và bảng dữ liệu theo đúng cấu trúc database backend.
- Làm cho các modal admin hiển thị bằng Portal để tránh bị che bởi layout.

Những gì đã làm

1. Luồng đăng nhập và phân quyền admin
- Khi đăng nhập thành công, nếu user có role ADMIN thì được chuyển thẳng tới /admin/dashboard.
- Thêm RoleGuard để chặn các route admin với người không có quyền.
- RoleGuard đọc accessToken và user từ localStorage rồi so role trước khi cho vào trang admin.

2. Dashboard admin theo kiểu single page
- Refactor Dashboard để có activePanel state.
- Sidebar không còn là điều hướng sang trang riêng cho sản phẩm/danh mục nữa.
- Các mục như Tổng quan, Quản lý sản phẩm, Quản lý danh mục đổi panel ngay trong dashboard.
- Mục Đơn hàng và Khách hàng vẫn là route riêng hoặc placeholder nếu chưa triển khai đầy đủ.

3. Sidebar admin
- Sửa active state để item đang chọn được highlight đúng.
- Fix lỗi trước đó khi bấm sang menu khác mà Tổng quan vẫn còn active.
- Logout admin đã được nối với authService.logout() và xóa localStorage:
  - accessToken
  - refreshToken
  - user
  - profile
- Sau logout sẽ quay về /login.

4. Quản lý danh mục
- Đồng bộ với schema thật của backend:
  - category_code
  - category_name
  - description
  - created_at
- Mỗi lần chỉ hiển thị 6 danh mục trên một trang.
- Modal thêm/sửa danh mục được bọc bằng Portal.
- Bỏ khối “Danh mục nổi bật” như yêu cầu trước đó.
- Giao diện giữ lại phần bảng chính và ghi chú backend tối giản.

5. Quản lý sản phẩm
- Rà soát lại schema database trước khi sửa modal.
- Đồng bộ sản phẩm theo backend:
  - category_id
  - product_code
  - product_name
  - default_specs
  - created_at
- Sửa modal thêm sản phẩm để dùng đúng field thật của DB.
- Đổi style modal sản phẩm cho giống modal quản lý danh mục.
- Modal sản phẩm có Portal.
- Dropdown danh mục lấy từ backend categories.

6. Bảng sản phẩm và import dữ liệu
- Thêm nút tải file mẫu.
- Thêm nút import dữ liệu bằng Excel.
- Upload dùng FormData với key file.
- Backend endpoint được dùng:
  - GET /api/imports/template
  - POST /api/imports/upload
- Có modal import riêng và hiển thị batchId sau khi upload thành công.

7. Sửa mapping API frontend
- getProducts đã được map lại để frontend dùng query đúng với backend:
  - search thay cho q
  - category_id thay cho category
- Điều này giúp lọc/tìm kiếm chạy đúng dữ liệu thật thay vì field cũ.

8. Tổ chức modal bằng Portal
- Các modal admin đều được đưa vào Portal để render ra document.body.
- Cách này giúp modal nổi lên trên toàn bộ dashboard, không bị ảnh hưởng bởi overflow hay z-index của layout.

Ghi chú quan trọng
- Prisma schema là nguồn sự thật cho field của sản phẩm và danh mục.
- ProductForm hiện không còn dùng các field cũ kiểu name / sku / price / status.
- Category modal và Product modal đã được kéo về cùng một ngôn ngữ thiết kế.
- Một số mục trong admin vẫn có thể là placeholder nếu backend hoặc UI của chúng chưa được hoàn thiện tiếp.

Trạng thái hiện tại
- Phần admin core đã chạy theo mô hình dashboard nội bộ.
- Form sản phẩm và danh mục đã bám đúng schema backend.
- Import file sản phẩm đã có UI.
- Logout admin hoạt động.
- Modal admin đã dùng Portal.

Nếu muốn đọc tiếp phần sau, có thể viết tiếp thành "admin part 2" cho các mục như:
- quản lý đơn hàng
- quản lý khách hàng
- tối ưu dashboard overview
- chuẩn hóa response API và validation cho import
