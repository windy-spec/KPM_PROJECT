BRD - LẬP BÁO GIÁ TỰ ĐỘNG (Pricing Engine Form)

Mục tiêu
- Màn hình cho phép Sales / Admin nhập tập các sản phẩm (dynamic form array) và gọi Pricing Engine (backend) để tự động bóc tách khối lượng, nhân công, vật tư và trả về báo giá (quotation).
- Giao diện gồm 2 cột: trái là danh sách item (form per item), phải là hóa đơn tạm tính (preview).

File chính
- `frontend/src/pages/quotations/PricingForm.jsx` — component React đơn trang, dùng hooks, kết nối đến `frontend/src/services/admin.service.js`.

Luồng hoạt động & code walk-through
1) Lookups (mount)
- `useEffect` gọi `loadLookups()`:
  - `adminService.getProducts({page,limit})` — lấy products để hiển thị dropdown `Sản phẩm`.
  - `adminService.getMaterials()` — lấy materials cho dropdown `Loại Vật Tư`.
  - `adminService.getMaterialThickness()` — lấy toàn bộ độ dày (sau đó FE lọc cho vật tư tương ứng).
  - `adminService.getPaintTypes()` — lấy các loại sơn.
- Kết quả lưu vào `products`, `materials`, `thicknessList`, `paints`.

2) Items state
- `items` là mảng các object: { id, product_id, width, height, material_id, thickness_value, paint_id, note }
- `addItem()` push 1 item mới (mỗi item có unique `id` bởi Date.now()).
- `removeItem(id)` loại bỏ item. `updateItem(id, patch)` cập nhật partial.

3) Cascading Độ dày
- `thicknessOptionsFor(materialId)` trả về `thicknessList.filter(t => t.material_id === materialId)` — FE chỉ hiển thị độ dày tương ứng với `material_id` đã chọn.
- Khi user thay `material_id`, code cũng reset `thickness_value` để tránh mismatch.

4) Validation (FE-critical rules)
- `validateAll()` kiểm tra:
  - Mỗi item có `product_id`, `material_id`, `thickness_value`, `paint_id`.
  - `width` và `height` phải là số > 0.
- Nếu bất kỳ item nào không thỏa → `TÍNH TOÁN & LÊN BÁO GIÁ` bị vô hiệu hóa.

5) Submit
- Khi người dùng click nút `TÍNH TOÁN & LÊN BÁO GIÁ` → `handleCalculate()`:
  - Gọi `adminService.calculateQuotation({ items })` với payload đã chuẩn hoá (number fields parsed).
  - Nếu thành công, xem `res.data.data` là `quotePreview` (structure tuỳ backend). FE lưu vào `quotePreview` và render preview ở cột phải.
  - Nếu lỗi, hiển thị `showError(...)` với message backend (giúp debug và hiển thị validate message từ BE).

6) Hóa đơn tạm tính (Preview)
- Nếu backend trả `quotePreview` có `total` và `items` array, FE hiển thị tổng và list items với các trường đã tính.
- Đây chỉ là preview; sau này có thể thêm nút "Lưu báo giá" để gọi API tạo quotation thực tế.

Giao diện & UX notes
- Left column: each item boxed, giống phong cách admin (rounded, border, padding).
- Right column: sticky summary card showing total and per-item breakdown.
- Buttons: `+ Thêm Sản Phẩm Mới` và `TÍNH TOÁN & LÊN BÁO GIÁ` (màu nổi). Nút tính bị disable khi validation fail.

Các assumption kỹ thuật
- Endpoint backend `POST /api/quotations/calculate` nhận payload `items` và trả một object có `total`, `items` với pricing detail. (Implementation backend is assumed available.)
- `admin.service.calculateQuotation` được tạo để gọi endpoint trên.
- `getMaterialThickness` có thể trả toàn bộ hoặc chấp nhận params; code hiện lấy toàn bộ và filter client-side để đảm bảo cascading selection.

Tổ chức mã & mở rộng
- Component nhỏ, không có state management phức tạp (no redux). Dễ tách ra thành form-item component (`QuotationItem.jsx`) nếu muốn.
- Nên thêm debounce/auto-calc nếu muốn tự động tính sau mỗi thay đổi (hiện tắt để tránh spam request).
- Nên thêm UX cho lỗi từng item (highlight invalid field) để hỗ trợ người dùng.

Cách test nhanh
1) Chạy frontend dev server:
```bash
cd frontend
npm install
npm run dev
```
2) Navigate tới route where you mount `PricingForm` (see notes below).
3) Add items, fill fields, ensure width/height > 0, click `TÍNH TOÁN & LÊN BÁO GIÁ`.
4) Check network tab for POST `/api/quotations/calculate` and inspect response.

Mounting the page
- This file is created under `frontend/src/pages/quotations/PricingForm.jsx`.
- To view it, add a route in your router (e.g., `App.jsx`) or render it inside an admin panel. Example:
  - import PricingForm from './pages/quotations/PricingForm';
  - <Route path="/admin/pricing" element={<PricingForm/>} />

Giải thích sâu về code (key functions)
- `loadLookups()` — paralell fetch lookups; handles missing `.data.data` shapes.
- `addItem()` — pushes skeleton item; id is Date.now for simplicity; can be replaced by uuid.
- `thicknessOptionsFor(materialId)` — enforces cascading thickness; avoids calling backend per-chosen material to reduce chattiness. If backend supports query `?material_id=...` we can change `getMaterialThickness({material_id})` to fetch only relevant options.
- `validateAll()` — enforces business rule: width/height >0 and required ids present. This prevents malformed payloads that backend would reject.
- `handleCalculate()` — constructs sanitized payload and calls `adminService.calculateQuotation`. Always wrap network calls in try/catch and provide user-friendly messages.

Kết luận
- Mình đã thiết kế `PricingForm` theo BRD, với dynamic items, cascading thickness, FE validation, and a clear API integration point for the pricing engine.
- Nếu bạn muốn, mình sẽ tiếp tục:
  - Tách từng item thành component riêng, thêm validation messages inline.
  - Tự động tính (auto-calc) sau mỗi thay đổi với debounce.
  - Thêm nút "Lưu báo giá" để persist quotation.
