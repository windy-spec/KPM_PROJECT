BÁO CÁO LỖI VÀ CÁCH KHẮC PHỤC LUỒNG TRỪ KHO (WAREHOUSE FLOW)

1. MÔ TẢ VẤN ĐỀ (VÌ SAO LUỒNG KHÔNG HOẠT ĐỘNG)
- Quá trình luồng Đơn hàng đi xuống Kho là: Admin duyệt đơn -> Tính toán số lượng vật tư cần tiêu hao (lưu vào biến `material_requirements` của Đơn hàng) -> Thủ kho dựa vào đó để đối chiếu kho thực tế và ấn "Xác nhận xuất kho" để trừ hàng.
- Tuy nhiên, trong code ở `order.service.js` (hàm `approveOrderAndRequestMaterials`), code cũ bị sửa thành: 
`const consumedQty = (parseFloat(comp.default_waste) || 0) * productQty;`
- Nguyên nhân lõi: Dữ liệu JSON `components` của mỗi sản phẩm (Product) được sinh ra từ màn hình Admin (file `ProductComponentsEditor.jsx`) không lưu cấu hình hao phí ở biến `default_waste`. Thực tế, hao phí được lưu trong một object tên là `waste_configs` (ví dụ: `comp.waste_configs[matId].rate`) hoặc fallback là `waste_rate`.
- Do code Backend lấy trường `default_waste` không tồn tại, nên kết quả `consumedQty` luôn bằng 0. 
- Hệ quả: Danh sách vật tư yêu cầu `material_requirements` trở thành một mảng rỗng `{}`. Khi mảng này đi xuống Kho, Thủ kho ấn "Xác nhận xuất kho" thì vòng lặp kiểm tra cũng bằng 0. Hệ thống cho rằng đơn hàng này "Không cần vật tư nào cả" và tự nhảy sang trạng thái Đang Sản Xuất (MANUFACTURING) mà bỏ qua hoàn toàn việc trừ kho.

2. PHƯƠNG ÁN KHẮC PHỤC
- Tôi đã can thiệp và sửa lại logic lấy định mức tiêu hao trong file `backend/nodejs/services/order.service.js`.
- Logic mới đảm bảo độ chính xác và tương thích ngược:
```javascript
  // Ưu tiên lấy định mức từ waste_configs theo đúng cấu trúc JSON của FE
  let waste = 0;
  if (matId && comp.waste_configs && comp.waste_configs[matId] && comp.waste_configs[matId].rate !== undefined) {
    waste = parseFloat(comp.waste_configs[matId].rate);
  } else {
    // Fallback nếu không có waste_configs
    waste = parseFloat(comp.default_waste) || parseFloat(comp.waste_rate) || 0;
  }
```

3. KẾT QUẢ ĐẠT ĐƯỢC
- Kể từ giờ, khi Admin "Duyệt & Bóc tách", hệ thống sẽ tính toán chính xác số lượng hao phí thực tế của từng vật liệu.
- Mảng `material_requirements` sẽ được gán số liệu chuẩn.
- Khi Thủ kho xác nhận xuất kho, vòng lặp đối chiếu kho sẽ hoạt động đúng, trừ hàng trên Database và tạo log "EXPORT" như quy trình chuẩn.
